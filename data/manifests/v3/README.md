# Corpus v3 sources

Built by `data/build_corpus_v3.py` (sources in `data/registries.py`). Corpus v3 =
corpus v2 + more, and more diverse, licensed data, without depending on Hugging Face.

| store        | contents                                                                                   |
|--------------|--------------------------------------------------------------------------------------------|
| `code-v3`    | `code-v2` + source code of the new packages below                                          |
| `general-v3` | `general-v2` + prose docs of those packages + FineWeb-Edu (only if huggingface.co is reachable) |
| `base-v3`    | `code-v3` + `general-v3` (same layout as the v2 stores, plus `docs.sha1`)                  |

## Registries

All requests are sequential, send a `forge-corpus-v3/1.0` User-Agent (set
`FORGE_CORPUS_CONTACT` to append a contact address), keep a per-host minimum
interval (crates.io 1 s, rubygems.org 0.2 s, hackage 0.3 s, Maven Central 0.25 s)
and back off on 429/503 using `Retry-After`. Only registry APIs and indexes are
used; no HTML page is scraped. Packages that corpus v2 already used
(`data/cache/v2/done.jsonl`, else `data/manifests/v2/sources.json`) are skipped.

| registry   | new ecosystem | how popular packages are chosen                                              | archive                         | licence read from                         |
|------------|---------------|------------------------------------------------------------------------------|---------------------------------|-------------------------------------------|
| `maven`    | Java/Kotlin/Scala | curated list of ~290 widely used artifacts (`MAVEN_ARTIFACTS`; Central's search API is not reachable here); newest stable version from `maven-metadata.xml` | `*-sources.jar`                 | POM `<licenses>`, following `<parent>` up to 4 levels |
| `rubygems` | Ruby          | `/api/v1/search.json` over ~70 keywords, ranked by the API's `downloads`     | `.gem` (`data.tar.gz`), sha256 checked against the API | API `licenses`                     |
| `hackage`  | Haskell       | `/packages/top` (JSON), ranked by recent downloads                           | `name-version.tar.gz`           | `.cabal` `license` field (BSD3 -> BSD-3-Clause, PublicDomain -> Public Domain) |
| `pypi`     | (v2)          | hugovk/top-pypi-packages (30-day downloads), beyond the ones v2 used         | sdist                           | JSON API `license_expression`/`license`/classifiers |
| `npm`      | (v2)          | registry search API, popularity-weighted, ~100 keyword queries               | tarball                         | `package.json` `license`                  |
| `go`       | (v2)          | curated list of ~250 widely imported modules (no popularity API)             | proxy.golang.org module zip     | root `LICENSE` text, classified           |
| `crates`   | (v2)          | crates.io API `/api/v1/crates?sort=downloads`                                | `.crate` from static.crates.io  | `Cargo.toml` `license`                    |

Prose ("general") files: `.md`, `.rst`, `.txt`, `.rdoc`, `.markdown`, `.adoc` and the
javadoc prose pages `package.html` / `overview.html` (converted to text). Licence,
copying, changelog/history/news files and anything under test directories are not
prose. Haddock and javadoc comments stay inside the code files; generated javadoc
/ haddock HTML is not downloaded.

FineWeb-Edu (`HuggingFaceFW/fineweb-edu`, ODC-By 1.0) is added only when
`https://huggingface.co/api/datasets/HuggingFaceFW/fineweb-edu` answers at build
time (`--fineweb-share` of `--target-tokens`, default 0.5); otherwise the build
logs `huggingface.co unreachable: FineWeb-Edu skipped`. `--parquet FILE` reads a
local copy instead.

Reachability measured from the build container on 2026-10-07: pypi.org,
files.pythonhosted.org, registry.npmjs.org, proxy.golang.org, index.crates.io,
static.crates.io, crates.io API, repo1.maven.org, rubygems.org, hackage.haskell.org
and raw.githubusercontent.com answer; huggingface.co, search.maven.org,
central.sonatype.com, repo.hex.pm, metacpan and stackage.org do not.

## Rules (as v1/v2)

* Licence allow-list of v1/v2 (MIT, BSD, Apache, PSF, ISC, Unlicense, CC0, Zlib,
  0BSD, public domain). The deny-list of v1/v2 (GPL, LGPL, AGPL, MPL, EUPL, SSPL,
  CC-BY-SA, Commons Clause, proprietary) is extended to spelled-out and versioned
  names (`GNU ... General Public License`, `GPLv3`, `LGPLv2.1`, `Eclipse Public`,
  `EPL-2.0`, `CDDL`, `ShareAlike`, ...); a licence string that mentions any of them
  is rejected even next to a permissive one. Unknown licences are rejected.
* Quality filters of v2 (SCP `corpora.is_quality_code`, `data_pipeline.is_quality`).
  New in v3: code files whose first 2000 characters mark them as generated
  (`Code generated ... DO NOT EDIT`, `@generated`, `Bindings generated by`,
  `auto-generated`, ...) are dropped; e.g. `windows-sys` is ~1 M tokens of bindgen output.
* Exact dedup: sha1 of whitespace-normalised text across every source, including
  every corpus v2 document (`data/cache/v2/docs`). `base-v3/docs.sha1` stores the
  sorted 20-byte digests of all v2 + v3 documents for later corpora.
* 13-gram decontamination against HumanEval, MBPP (including `test_list`) and GSM8K.
* ~1 % validation split by document hash; `forge tokenize` with `<eos>` (8190) after
  every document; all stores share `data/stores/base/tokenizer.json`.

## Files written here by the build

* `sources.json` - one record per package (and FineWeb file): `task`, `registry`,
  `name`, `version`, `license`, `license_from`, `url` + `sha256` of the archive,
  `authors`, `homepage`, `attribution`, `status` (`ok`, `rejected-licence`,
  `no-sdist`, `no-sources`, `unavailable`, `checksum-mismatch`, `error: ...`),
  `files`, `kept`, `chars`.
* `filters.json` - documents dropped per filter and kept per registry.
* `stores.json` - store manifests, package status per registry, FineWeb status,
  licence policy, dedup and decontamination summary.

## Building

```
python3 data/build_corpus_v3.py --dry-run                 # plan only
nice -n 15 python3 data/build_corpus_v3.py                # 400 M new tokens, <= 6 GB on disk
python3 data/build_corpus_v3.py --limit 2 --root DIR      # smoke run
```

The build is one nice(15) process and resumable (`data/cache/v3/done.jsonl`; a
rerun continues). `--target-tokens` bounds the new tokens, `--max-disk-gb` the
footprint of cache + the three stores (and 1 GB of free disk is always left).
Stores are staged in `data/out/.v3-staging` and moved into place with `base-v3`
last; then the document cache is deleted (`--keep-cache` keeps it). A finished
build is not redone unless `--fresh` is given.
